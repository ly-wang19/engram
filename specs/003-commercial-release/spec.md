# 功能规格：Engram 0.1.0 商业交付版

**Feature Branch**: `codex/commercial-release-v0.1.0`

**Created**: 2026-07-14

**Status**: Completed

**Input**: 用户要求交付一个阶段性终版，使 Engram 能作为可安装、可自托管、可验证、可授权的产品交给真实用户使用。

## 为什么做这个功能

Engram 已经具备长期记忆核心、持久化、多租户服务、HTTP/MCP/TypeScript 接入面和可复现实验，
但“代码能跑”还不等于“可以交付”。本阶段要把现有能力收束成一个边界清楚的 0.1.0 商业交付版：
默认安全、租户隔离、数据可持久化与删除、部署路径可复现、版本和许可证一致、失败时能被运维发现。

本阶段的商业化边界是**单节点自托管与商业授权交付**。它不宣称已经具备多区域高可用、无限水平扩展、
监管认证或托管云 SLA；这些能力需要后续独立规格和真实压测证明。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 安全地部署并持续运行（Priority: P1）

一个客户或运维人员希望在自己的机器上部署 Engram。他们按照中文部署文档配置持久化目录和访问密钥，
启动服务后能看到明确的存活与就绪状态；未配置鉴权时服务不会被误判为可对外使用，重启后数据仍然存在。

**Why this priority**: 商业交付首先必须避免默认裸奔、数据丢失和“进程在但服务不可用”的假健康。

**Independent Test**: 在全新目录中完成一次受保护部署，写入一条记忆，重启服务，再次召回该记忆；
然后移除鉴权配置，确认就绪检查失败且业务接口拒绝访问。

**Acceptance Scenarios**:

1. **Given** 运维人员提供有效访问密钥和可写数据目录，**When** 启动标准部署包，**Then** 服务报告已就绪且受保护接口只接受有效密钥。
2. **Given** 服务没有配置访问密钥且没有显式启用开发开放模式，**When** 运维系统检查服务状态，**Then** 进程可被识别为存活，但服务不会报告可接收业务流量。
3. **Given** 用户已经写入并固化记忆，**When** 服务正常重启，**Then** 原始情节、事实、图关系和更新历史均可恢复。
4. **Given** 请求超过产品声明的输入上限，**When** 请求到达服务，**Then** 服务在进入记忆处理前拒绝它并返回可理解的错误。

---

### User Story 2 - 以隔离且可审计的方式接入应用（Priority: P2）

一个应用开发者希望通过 HTTP、MCP 或 SDK 给自己的 Agent 增加长期记忆。不同客户的凭据必须解析到不同命名空间，
恶意或特殊字符命名空间不能越过数据根目录、互相碰撞或删除其他客户的数据。用户可以查看、导出、更正和删除自己的记忆。

**Why this priority**: 租户隔离和数据权利是面向真实客户的最低信任基础。

**Independent Test**: 使用两个租户和一组包含路径分隔符、点目录、Unicode、空白及相似字符的命名空间，
分别写入、读取、导出和删除；确认数据目录不越界、命名空间不碰撞、删除只影响目标租户。

**Acceptance Scenarios**:

1. **Given** 两个访问密钥映射到两个租户，**When** 两者写入相同主题的不同事实，**Then** 任一租户都无法读取、修改、导出或删除另一租户的内容。
2. **Given** 命名空间含有路径控制字符或规范化后可能相同的字符，**When** 系统创建其持久化位置，**Then** 位置始终位于数据根目录内且与其他原始命名空间唯一对应。
3. **Given** 客户轮换访问密钥但保持租户身份不变，**When** 新密钥生效，**Then** 客户仍访问同一份记忆，旧密钥可从配置中撤销。
4. **Given** 用户明确执行导出、更正或删除，**When** 操作完成，**Then** 返回结果可审计且不会静默覆盖历史或扩大到其他命名空间。

---

### User Story 3 - 可验证地发布和支持 0.1.0（Priority: P3）

维护者希望任何 0.1.0 发布都经过同一组门禁：版本号一致、离线快速开始可运行、完整测试通过、
官方 SDK 与管理界面可构建、部署包可启动、公开基准数字仍能追溯到已提交日志。用户能找到安全策略、变更记录、
部署说明、许可证边界和问题反馈入口。

**Why this priority**: 商业版本必须可重复构建和支持，不能依赖发布者本机状态或口头说明。

**Independent Test**: 从干净检出执行发布检查，构建产品分发包、官方 SDK、管理界面和标准部署包，
并运行零配置检查与完整测试；任何版本漂移、缺失许可证或失败检查都会阻断发布。

**Acceptance Scenarios**:

1. **Given** 任一可发布组件版本与主版本不一致，**When** 执行发布门禁，**Then** 门禁失败并指出不一致位置。
2. **Given** 零配置路径、完整测试、SDK 构建或部署冒烟任一失败，**When** 执行发布门禁，**Then** 0.1.0 不得标记完成。
3. **Given** 用户准备评估或采购 Engram，**When** 阅读仓库文档，**Then** 能找到支持范围、安全边界、开源与商业许可差异、部署步骤和升级注意事项。
4. **Given** 本次没有修改检索算法，**When** 发布结果被记录，**Then** 不新增算法领先声明，也不把发布测试冒充算法效果实验。

### Edge Cases

- 同一租户配置多个有效密钥用于无停机轮换。
- 配置项包含空租户、空密钥、重复密钥映射到不同租户或格式错误。
- 数据目录只读、磁盘空间不足或已有旧版安全命名目录。
- 命名空间为 `.`、`..`、绝对路径、路径分隔符、仅空白、超长文本或非拉丁字符。
- 请求没有 `Content-Length`、声明长度不合法，或声明长度超过限制。
- 服务进程存活但鉴权缺失、数据目录不可写或核心组件初始化失败。
- 旧版普通租户目录和可信旧快照需要继续读取，升级不能静默丢失已有数据。
- 本机没有可选模型或外部服务时，离线确定性路径仍必须工作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 产品 MUST 提供一条有文档、可重复的单节点自托管部署路径，并使用持久化数据目录。
- **FR-002**: 生产部署 MUST 默认关闭开放访问；开放模式和共享匿名模式只能由操作者显式启用。
- **FR-003**: 系统 MUST 区分“进程存活”和“可接收业务流量”，鉴权缺失时不得报告业务就绪。
- **FR-004**: 系统 MUST 验证访问密钥配置，拒绝空值、格式错误及一个密钥映射多个租户的歧义配置。
- **FR-005**: 系统 MUST 支持同一租户配置多个密钥，以便密钥轮换；移除旧密钥后访问立即失效。
- **FR-006**: 每个原始命名空间 MUST 映射到数据根目录内唯一且确定的持久化位置。
- **FR-007**: 命名空间映射 MUST 阻止目录穿越、绝对路径逃逸、规范化碰撞和跨租户删除。
- **FR-008**: 升级到 0.1.0 MUST 保持对合法旧版命名空间目录和可信旧快照的读取与删除兼容。
- **FR-009**: 服务 MUST 在业务处理前拒绝超过可配置上限的请求，并为常用文本、查询、会话和分页参数设置边界。
- **FR-010**: 所有受保护响应 MUST 禁止缓存，并携带适合自托管管理界面的基础安全响应头。
- **FR-011**: 数据写入、重启恢复、导出、更正、精确删除和整租户删除 MUST 有自动化验收覆盖。
- **FR-012**: 产品分发包、服务自描述、官方 SDK 和管理界面 MUST 使用一致的 0.1.0 产品版本。
- **FR-013**: 发布门禁 MUST 验证许可证文件、版本一致性、包内容、中文/英文关键文档和公开证据日志完整性。
- **FR-014**: 发布前 MUST 通过离线快速开始、完整回归、官方 SDK/管理界面构建及标准部署冒烟。
- **FR-015**: 项目 MUST 提供中文优先的部署、安全、备份/恢复、升级、回滚、密钥轮换和已知边界文档。
- **FR-016**: 本次发布 MUST 更新架构优化地图和完整架构报告，标明服务边界、鉴权流、命名空间映射与发布门禁。
- **FR-017**: 本次发布 MUST 保持现有算法行为和公开基准数字不变；任何算法声明仍只接受已提交真实实验日志。

### Key Entities

- **Release**: 具有统一版本、变更记录、构建产物、验收证据和支持边界的阶段交付。
- **Credential Mapping**: 访问密钥到稳定租户身份的映射；允许一租户多密钥，不允许一密钥多租户。
- **Namespace Location**: 原始租户身份到安全、唯一、确定且位于数据根目录内的持久化位置。
- **Service Health**: 分为存活状态与就绪状态，并包含不泄露秘密的配置诊断信息。
- **Deployment Configuration**: 鉴权、数据目录、请求上限、模型后端和运行资源的显式配置集合。
- **Release Evidence**: 记录每项发布门禁、命令、结果和环境的可审计证据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新操作者可在 15 分钟内按中文文档启动一个受密钥保护、使用持久卷且报告就绪的实例。
- **SC-002**: 100% 的目录穿越、绝对路径、点目录、碰撞样例和 Unicode 命名空间测试均被安全隔离在数据根目录内。
- **SC-003**: 两租户交叉读取、修改、导出、单条删除和整租户删除测试的越权成功数为 0。
- **SC-004**: 写入后重启恢复测试保留 100% 的原始情节、事实、关系和 `supersedes` 历史。
- **SC-005**: 未配置鉴权的默认实例对所有受保护接口返回拒绝结果，且就绪状态为 false。
- **SC-006**: 超过配置上限的请求有 100% 在记忆写入前被拒绝，合法边界请求仍可成功处理。
- **SC-007**: 所有可发布组件的版本检查为 0.1.0，版本漂移样例会使发布门禁失败。
- **SC-008**: 离线快速开始、完整回归、官方 SDK、管理界面、产品分发包和标准部署冒烟全部通过，失败项为 0。
- **SC-009**: 安全、部署、许可、变更、升级/回滚和支持边界文档完整率为 100%，中英文入口互相可达。
- **SC-010**: 本次公开基准数字与已提交证据保持一致，新增无日志算法或规模声明数量为 0。

## Assumptions

- 0.1.0 面向单节点自托管、内网部署、开发者集成和商业授权评估，不承诺多区域高可用或监管认证。
- TLS、互联网边界防护和分布式限流由反向代理/API 网关承担；Engram 提供安全默认和明确部署契约。
- 默认持久化实现适合单机与中小规模工作负载；更大规模后端必须沿现有接口另行评测。
- 现有 83.6% LongMemEval_S 结果不因本次发布工程变更重新解释；本次不改算法，不跑新的 500 题算法实验。
- 商业授权的价格、SLA、赔偿和支持条款由双方合同确定，不在开源仓库中自动授予。

## Out of Scope

- 多区域主动容灾、自动分片、在线无损迁移和托管云控制面。
- SOC 2、ISO 27001、等保、HIPAA、GDPR 认证或法律合规结论。
- 按租户计量计费、订阅、发票和支付系统。
- 新检索算法、模型微调、500 题重新跑分或新的世界第一/SOTA 宣称。
- 企业 SSO、RBAC、审计日志外送和密钥管理服务集成；这些进入后续企业版规格。
